## 🍜 4. 日本餐飲生態與老饕防誤殺原則 (Foodie Precedence)

1. **嚴禁武斷設定「Google 4.0+ 一刀切硬門檻」**：
   - 日本大量頂級職人神店（頑固老爹、排隊規矩嚴格、座位狹窄），常因觀光客給負評而導致 Google 評分僅 3.5~3.7，但在 Tabelog 上老饕卻給出 3.8+ 百名店神級高分。
   - **系統底層策略**：以 **Google 3.5+ 寬鬆保底防誤殺老店**，排除連鎖快餐後保留候選。
2. **終極裁判權上繳 Tabelog (Review Precedence Contract)**：
   - Google 僅作為「800m 物理距離探針與市話取得器」，最終推薦順序與口感重排 100% 由 Tabelog 老饕口コミ與評分定奪。

## 📱 5. 審計抽屜「架構因果故事置頂」規範 (Causality-First Hierarchy)

為徹底根除「微觀決策被淹沒在長篇 JSON 下方、外來者讀不懂」的問題，6 維審計抽屜嚴格遵守以下資訊階層：

1. **節點標題與執行延遲**（例如：`🧠 State 1: 結構化意圖抽取 · ⏱️ 280ms`）
2. **節點責任描述**（模組職責摘要）
3. **⚡ 關鍵架構決策 ＆ 因果解讀（強制置頂！第一眼讀懂技術亮點）**：
   - 採用金色醒目邊框與背景（`#fffbeb` / `#d97706`），清晰陳述「為何走這條路、採取了什麼演算法策略、如何保護外部 API 額度」。
4. **📥 節點輸入 (Input Payload JSON)**
5. **📤 節點輸出 (Output Payload JSON)**
6. **💬 旅人手機端真實推播視圖 (Telegram Message Result)**：
   - **僅在終端推播節點 (`telegram_out`) 展開**，中段節點自動隱藏以保持審計專注。
